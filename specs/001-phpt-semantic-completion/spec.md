## Clarifications

### Session 2026-10-03

- Q: 终态判据一的「语言核心全量」是否涵盖 php-src `tests/` 顶层目录（现 harness 已纳入六目录约 780 例、348 个存量失败），还是仅指 Zend/tests？ → A: 涵盖——语言核心 = Zend/tests 全量 + `tests/` 顶层全部目录（R5 清点后一并纳入口径）；存量 348 失败随 Z 相清偿。
- Q: 门禁目录通道的「改动文件 → 验收目录」映射未命中时默认怎么做？ → A: fail-safe——未命中默认跑全部已纳入目录的 phpt 比对；映射表显式维护，引擎核心文件映射到全部目录。
- Q: 被标记「环境不可得」的用例在环境后来可得时是否必须强制复跑并重新归类？ → A: 登记即债——清单持续追踪，环境可得时（相收尾 / 全量通道）强制复跑并按语义失败重新分诊；分类是临时态不是终态。
- Q: 国际化子集的验收锚点是应用场景差分还是实现函数面清单？ → A: 场景锚——验收 = 命名的 Carbon/Laravel 本地化场景在差分用例库中逐字节一致；实现函数面清单仅作记账，不构成验收边界。
- Q: Z 相清偿中挖出解析器/引擎数据形态级深度工程时批次如何推进？ → A: 立即登记拆独立里程碑、相关用例先顺延、批次继续推进；相出口前盘点登记项处置（修复或顺延），不允许既不修也不记的第三态。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在本机恢复完整验证设施 (Priority: P1)

phpbeam 的贡献者在开发机迁移后（旧机器的基线、php-src 路径、数据库容器全部失效），需要在本机把验证设施完全恢复：跑 phpt 验收套件、跑数据库差分、跑发布门禁。恢复之后，任何人按文档应能从当前仓库状态复现同一套门禁结果，而不依赖某台特定历史机器。

**Why this priority**: 语义完备主线的一切工作都以 phpt 验收套件可运行、门禁可比对为前提；设施瘫痪时连「现状是多少失败」都无法回答，是全计划的第一张多米诺。

**Independent Test**: 在本机从仓库当前状态出发，按 PLAN 的环境清单操作后：门禁快通道全绿、MySQL 差分用例全绿、phpt 套件真实执行（不再因缺 php-src 树而整目录跳过）。

**Acceptance Scenarios**:

1. **Given** 本机无基线文件且旧 php-src 路径失效，**When** 贡献者按重钉后的默认配置运行门禁，**Then** phpt 套件在本机 php-src 树上真实执行，基线文件从绿套件重建，门禁通过。
2. **Given** 20,766 例验收用例不可能每次提交全量运行，**When** 贡献者提交一个普通改动，**Then** 门禁按「快通道（非 phpt）+ 相关目录通道」执行，单次常规验证在分钟级完成；收尾时才跑全量通道。
3. **Given** 失败基线此前是单一整表，**When** 贡献者只改动某几个目录对应的模块，**Then** 门禁只比对这些目录的分片基线，且分片基线与全量基线可互相校验一致。
4. **Given** 金标准解释器与验收套件版本随环境更新（oracle 8.4.2→8.4.17、套件源 8.4.24→8.4.25），**When** 基线重建完成，**Then** 版本漂移的影响面（受影响用例数与处置）被量化并登记在风险表，而非静默吸收。

---

### User Story 2 - 语言核心考场全量开门（Zend/tests 清偿） (Priority: P2)

贡献者把 php-src 官方语言语义主考场（Zend/tests 全量 4,969 例，连同 `tests/` 顶层既有六目录的 348 个存量失败）纳入验收并清偿：先修掉两枚已知的阻断性缺陷（trait 嵌套展平失控循环、类存在性探测时自动加载注册进被丢弃的解释器状态），再按子目录分批纳入、逐批分诊、失败三选一（修复 / 豁免登记 / 时间盒超时顺延登记）。此故事完成后，解释器内核语义被官方套件钉死，后续扩展目录的失败不再掺杂引擎根因噪声。

**Why this priority**: 引擎根因缺陷会同时污染所有扩展目录的失败集——先清语言核心，后续每个扩展目录的失败才是「真失败」；这也是编译后端冻结判据（失败集只剩豁免类）最大的一块前置。

**Independent Test**: Zend/tests 全量纳入后跑全量通道，失败集与登记集（豁免+顺延）作差为空；同时 Laravel/WordPress/Composer 三项活体冒烟各跑一轮全过。

**Acceptance Scenarios**:

1. **Given** 两枚阻断缺陷存在（trait 展平失控消耗内存、自动加载状态丢失），**When** 贡献者运行此前触发缺陷的 Laravel 工匠命令路径，**Then** 命令正常完成，不再出现失控资源消耗或静默丢失的注册状态。
2. **Given** Zend/tests 从未纳入过 harness，**When** 按子目录分批纳入并逐批执行「纳入→全量分诊→录基线→失败三选一→基线只收缩」，**Then** 每批以独立提交过门禁，全程无静默跳过的失败用例。
3. **Given** 分诊产出的失败按根因聚类，**When** 某一失败项超出 2 小时时间盒，**Then** 它被登记进顺延清单（带根因与再入条件）而不是被无声搁置。
4. **Given** 清偿完成，**When** 以机械方式比对失败集与登记集（豁免∪顺延，相出口口径），**Then** 差集为空——该判定不依赖任何人的记忆。

### User Story 3 - 已实现扩展目录收割（T1 纯逻辑 + T2/T3 客户端） (Priority: P3)

贡献者对已经实现过的扩展，把其官方验收目录逐个纳入并清偿：纯逻辑扩展目录（标准库/日期/SPL/反射/多字节字符串/会话等 18 个目录约 11.5k 例）与外部客户端目录（DOM/Phar/mysqli/openssl/curl/zlib/zip/sockets/PDO 家族/sqlite3/pgsql/xml/posix/ftp 约 3.5k 例）。对外部环境有依赖的用例（真数据库、真服务器、外网），分诊时必须区分「环境不可得」与「语义不符」，前者单列不误计。

**Why this priority**: 这些扩展的函数面已实现，但其官方用例从未纳入验收——「已实现」与「语义等价已证明」之间的差距正是本故事要消除的；同时顺延清单中对应扩展的历史欠账在此自然消化。

**Independent Test**: 每纳入一个目录即形成独立可验证的一批：该目录失败集收敛到只剩登记项，基线分片只收缩。

**Acceptance Scenarios**:

1. **Given** 某纯逻辑扩展目录（如标准库 3,766 例）首次纳入，**When** 全量分诊按失败类别聚类，**Then** 每一失败类要么被修复、要么获用例级豁免（写明理由）、要么带根因进顺延清单。
2. **Given** 某数据库扩展目录的用例需要真实数据库服务，**When** 贡献者启动本机数据库容器后运行，**Then** 环境相关的跳过与真实的语义失败在分诊报表中分开列示。
3. **Given** 目录清偿完成，**When** 后续任何提交触碰该目录对应模块，**Then** 门禁对该目录分片基线执行只收缩校验。

---

### User Story 4 - E 组扩展以子集口径落地（intl/gd/sodium + 两节设计文档） (Priority: P4)

面向在 BEAM 上跑 Laravel/Carbon 的最终用户：国际化（Carbon 本地化所需子集，不追 ICU 全量移植）、图像元信息（无依赖件先行，图像生成的字节级复刻按架构性差异登记豁免）、现代加密（密码学库映射，先例已证可行）三个扩展按「实测圈定子集」落地并纳入子集用例；另产出 FFI 桥与进程模型两节设计文档（设计先行，不写实现）。

**Why this priority**: 这三个扩展函数面大而无对应的全量验收信号，不钉死边界就是无底洞；子集口径既服务真实用户（Carbon/Laravel），又守住验收判据的可达成性。

**Independent Test**: 国际化子集（区域设置泛型/数字格式化/日期格式化）支撑 Carbon 本地化路径跑通；图像元信息函数无外部依赖即可差分；加密扩展子集用例清偿；两节设计文档独立成文可评审。

**Acceptance Scenarios**:

1. **Given** Carbon 的本地化路径依赖国际化子集，**When** 在 phpbeam 上运行该路径，**Then** 输出与金标准解释器一致，且子集外的官方用例全部带豁免登记（理由：子集边界）。
2. **Given** 图像生成类官方用例要求与参考实现字节级一致，**When** 分诊评估确认两类图像栈无法字节对齐，**Then** 该类用例按架构性差异登记豁免，元信息/几何类用例正常清偿。
3. **Given** 进程模型扩展有官方用例 58 例，**When** 设计文档定稿，**Then** 其中可在当前形态下落地的用例随之纳入清偿，其余登记。
4. **Given** 加密扩展以密码学原语库映射实现，**When** 其子集用例纳入，**Then** 失败项按同款「三选一」纪律处置。

### User Story 5 - 编译后端去风险尖曝（F0） (Priority: P5)

贡献者在语言核心清偿完成后，用一次时间盒尖曝验证编译后端的核心假设：把一个用户函数从 PHP 抽象语法树编译到宿主语言抽象语法树并端到端运行，以现有解释器输出为逐字节基准。产出是可行性结论与接缝风险清单，尖曝代码明确标注为一次性验证品。

**Why this priority**: 编译后端是整个计划最大的不确定体，冻结判据达成前先用小成本买「路线是否成立」的答案；排在语言核心之后是因为基准（解释器）必须先钉死。

**Independent Test**: 选定的用户函数经编译路径运行的输出与解释器输出逐字节一致；结论文档（可行/不可行/条件可行 + 接缝清单）独立成文。

**Acceptance Scenarios**:

1. **Given** 解释器对选定函数的输出已由验收套件钉死，**When** 编译路径端到端运行同一函数，**Then** 两路输出逐字节一致。
2. **Given** 尖曝完成，**When** 贡献者查阅结论文档，**Then** 每个已识别的接缝风险都有对应的处置建议（不要求在本故事内解决）。

---

### User Story 6 - 终态判据可机械判定 (Priority: P6)

维护者在任何时点都能用一条命令回答「距离编译后端冻结判据还差多少」：失败集与豁免集的比对是机械的、可复现的，判据一（全套件口径）明确为「语言核心全量 + 已实现扩展目录全量 + 豁免扩展目录级登记」。

**Why this priority**: 原计划的冻结判据文字上成立但操作上不可判定（没有任何工作项指向它）；本故事把判据从「愿望」变成「仪表盘」。

**Independent Test**: 判定命令在任何提交点可运行，输出三集合（失败/豁免/顺延）的精确差集中是否有未登记项。

**Acceptance Scenarios**:

1. **Given** 豁免扩展清单（16 扩展 + 架构不适用项 + 编译类用例）已登记为目录级条目，**When** 判定命令运行，**Then** 输出仅列未登记的失败项（若为空即达冻结判据）。
2. **Given** 新失败出现在已清偿目录，**When** 门禁运行，**Then** 只收缩规则立即拦截该提交。

### Edge Cases

- 验收套件源与金标准解释器的版本漂移（8.4.24→8.4.25 期望文本、8.4.2→8.4.17 探测行为）：以本机版本为准重录基线，受影响用例单独分诊登记，不静默改判。
- 环境不可得的用例（数据库未启动、无真 FTP 服务器、外网被限）：必须与语义失败分列，不互相污染统计。
- 时间盒超时的深度引擎项（如需要改语法树元组形态的反射类型支持）：按顺延纪律登记并评估是否需独立里程碑，不允许在批次内无限展开。
- 图像库依赖不可得（依赖源被网络策略拦截）：该扩展整体降级为待命登记项，其余子集不受影响。
- 门禁全量通道单次运行超长（如超过 30 分钟）：按目录组拆分通道或调并行度，门禁语义不变。
- 测试进程残留占用端口导致后续运行挂起：门禁清扫步骤的效力在环境恢复时重新验证。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须将验收套件默认指向本机 php-src 8.4.25 树与金标准解释器 8.4.17，并把两处版本漂移登记为可量化的风险项（受影响用例数 + 处置）。
- **FR-002**: 系统必须能在本机完成依赖重落与构建（含网络受限的绕行路径），并验证既有本地补丁未被依赖刷新破坏。
- **FR-003**: 系统必须恢复数据库差分链路（容器启动 → 差分用例全绿），作为外部客户端扩展验收的前置。
- **FR-004**: 门禁必须提供三条通道——快通道（构建+非 phpt 全绿）、目录通道（仅改动相关目录的 phpt 分片比对）、全量通道（收尾跑全部已纳入目录）——且常规提交流程不要求跑全量通道。目录通道由显式维护的「改动文件 → 验收目录」映射表驱动；**映射未命中时必须 fail-safe 跑全部已纳入目录**，引擎核心文件映射到全部目录，不允许出现「不知道影响哪就跳过」的路径。
- **FR-005**: 失败基线必须按目录分片存储，支持分片与全量互相校验；基线重建只能从绿套件录制，重建后项目总账按本机事实重记。
- **FR-006**: 必须修复两枚阻断性缺陷（trait 嵌套展平失控循环、类存在性探测的自动加载状态丢失），修后对应活体冒烟路径可完整运行。
- **FR-007**: Zend/tests 全量必须按子目录分批纳入验收，每批执行「纳入→全量分诊（按失败类别聚类）→录基线→失败三选一（修复/用例级豁免登记/2 小时时间盒顺延登记）→基线只收缩→独立提交过门禁」；清偿中挖出的解析器/引擎数据形态级深度工程，必须立即登记并拆独立里程碑（相关用例先顺延、批次继续推进），相出口前盘点全部登记项的处置——不存在「既不修也不记」的第三态。
- **FR-008**: 已实现的纯逻辑扩展目录（18 个，约 11.5k 例）必须逐目录按 FR-007 同款纪律纳入清偿，历史顺延清单中对应项随批消化。
- **FR-009**: 已实现的外部客户端扩展目录（16 个，约 3.5k 例）必须逐目录纳入清偿，且分诊报表必须将「环境不可得」与「语义不符」分列；「环境不可得」是持续追踪的临时态——环境可得时（相收尾 / 全量通道）必须强制复跑并按语义失败重新分诊，不得作为终态分类。
- **FR-010**: 国际化扩展必须按 Carbon/Laravel 实测圈定子集落地，**验收锚点是场景差分**：命名的 Carbon/Laravel 本地化场景在差分用例库中逐字节一致即为达标，实现函数面清单仅作记账不构成验收边界；子集外官方用例逐条带理由豁免；不进行 ICU 全量移植。
- **FR-011**: 图像扩展必须以无外部依赖的元信息/几何函数先行落地；图像生成类用例按架构性差异走豁免登记，不追字节级一致。
- **FR-012**: 加密扩展（sodium）必须落地其可用原语映射面并纳入对应用例；FFI 桥与 pcntl 进程模型各产出独立可评审的设计文档（设计先行，不含实现）。
- **FR-013**: 必须执行一次时间盒限定的编译后端尖曝：单个用户函数端到端（源→编译路径→运行），与解释器输出逐字节比对；产出可行性结论与接缝清单，尖曝代码标注一次性。
- **FR-014**: 终态判据一必须明确口径为「语言核心全量 + 已实现扩展目录全量 + 豁免扩展目录级登记」，其中**语言核心 = Zend/tests 全量 + php-src `tests/` 顶层全部目录**（含既有六目录的 348 个存量失败，随 Z 相清偿；`tests/` 顶层零散目录由 R5 清点）；豁免登记含 16 扩展、架构不适用项与编译类用例；冻结判据的判定必须机械可执行，比对集只含豁免集——顺延项不计入达标（必须清偿或转豁免）。
- **FR-015**: 项目主计划（PLAN.md）必须按本规格重写，每个阶段带可验证的出口判据；决策记录（五项决策与落选方案）归档可溯。
- **FR-016**: 全程纪律不回退：每模块单独提交过门禁、失败基线只收缩、豁免/顺延逐条登记不静默跳过、里程碑移动单独提交。

### Key Entities

- **失败基线（目录分片）**: 每个已纳入验收目录的「当前已知失败用例集」；只允许收缩；分片与全量可互相校验。
- **豁免登记（exempt）**: 用例级或目录级的「不追」决定，每条含理由与解除条件；与顺延不同，豁免是结论性的。
- **顺延登记（deferred）**: 时间盒超时的待办，每条含根因与再入条件；会话/阶段收尾时清理，不是结论。
- **门禁通道（lane）**: 快/目录/全量三档验证策略，规定何种变更触发哪档。
- **判据口径**: 终态判据一的可执行定义（哪些目录属「必须全量」、哪些属「目录级豁免」）。
